# Code quality review (2026-10-08)

**Scope:** every TypeScript file in `lib/`, `app/api/` and `proxy.ts` (85 server files), and in
`app/` and `components/` (145 UI files). This was a non-functional pass. It changed no behaviour,
response, schema, auth decision, Stripe flow, visible design or animation.

**Headline:** the codebase was already clean. There was no `any`, no `@ts-ignore` or
`eslint-disable`, and no unused imports or locals. eslint and tsc were clean on main, and the
security-critical files were already commented. The pass therefore added explanation where a
future developer is most likely to misread intent, and fixed a handful of small, provably safe
issues. Everything larger is listed below as deferred, with the reason.

Checked and sound:
- The webhook verifies the signature before parsing anything, and PAID is terminal with conditional writes.
- Checkout takes the amount only from the stored invoice.
- Documents are authorised through RLS before the 60-second signed URL is minted.
- PostgREST filter inputs are sanitised.
- The contact form has a real byte limit and guards against header injection, and both emails escape HTML.
- Invitation completion requires a verified email.
- The only `dangerouslySetInnerHTML` is JSON-LD, with `<` escaped, and no server secret reaches a client component.
- There are no unhandled promises.

## Why the larger items were not done here

Each item above either changes a contract (status codes, schemas), changes behaviour a visitor or
operator can see, or needs production access to verify. The brief for this PR excluded all three.
Each one is small enough for its own reviewable PR.
